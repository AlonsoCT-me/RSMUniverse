## Propuesta de datos Shopify (sin crear recursos)

| Dato React | Destino propuesto | Decisión y validación |
|---|---|---|
| id slug / name | handle / product.title | Conservar nombres; conciliar handles/IDs reales, no asumir igualdad con Shopify. |
| price / priceAmount | variant.price + formato monetario nativo | Precio $1,599 es demostrativo; no importar como precio confirmado. No calcular importes con strings ni hardcodear MXN en mercados. |
| collectionId | collections Core y Special | Membresía administrada; orden explícito aprobado. Collection label no equivale a vendor. |
| collectionLabel | metafield de línea/modelo si no basta product.type | Mantener Core Cap/Special Edition como información secundaria; no alterar vendor para estilizar card. |
| images + alt/view | product.media, alt de media | Orden de fotos real; view puede alimentar texto accesible, sin adivinar imágenes faltantes. |
| colorPattern / swatch | option Color/Patrón solo si es elección vendible; si no, metafield informativo | No crear variantes falsas para mostrar un círculo. Confirmar swatch de categoría/opción real y capacidades nativas. |
| attributes.model | metafield de producto de texto | Puede diferir del título; verificar si dato ya existe en catálogo Shopify. |
| attributes.size | opción Talla si modifica variante vendible; si solo atributo, metafield | Nunca convertir “Por confirmar” en opción comprable. |
| material / closure | metafields de texto aprobados | Conservar vacío o mensaje pendiente en QA; no afirmar cuero/gamuza/composición por foto. |
| description | descripción nativa | Revisar exactitud y separar hechos de copy editorial. |
| care / políticas | página/policy/accordions dinámicos | Vincular instrucciones oficiales por producto y políticas configuradas. |

Definir primero tipos/validaciones y propietario de campos de tienda; después poblar valores aprobados; por último conectar fuentes dinámicas/Liquid en bloques existentes. Es una propuesta de contenido para tema, no una app ni una instrucción de crear TOML de aplicación. Los identificadores definitivos de metafields quedan pendientes de verificar el modelo ya existente. Metaobjects solo si se necesita compartir módulos editoriales estructurados entre varios productos/páginas; no añadirlos para texto único editable en sección.

La pendiente `size` en Gamuza y Super Cajeta existe aunque haya cierre ajustable descrito: no demuestra medidas confirmadas. El estado comercial real disponible/agotado se obtiene de variantes Shopify; `.availability` en React es texto de checkout con un punto verde, sin inventario.
