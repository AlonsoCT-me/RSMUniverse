## Fuentes y grado de certeza

Prototipo: archivos reales de `src/pages`, `src/components`, tipos, datos y SCSS. Tema consultado exclusivamente en lectura: `/Users/alonsoct/Sites/shopify/rsm-shopify` (en adelante **T**). Un archivo presente no demuestra que esté activo en QA.

**CÓDIGO LOCAL** confirma existencia y capacidad estática, no apariencia, despliegue, aprobación de RSM ni prueba funcional en tienda. NATIVE reutiliza una capacidad directa; CONFIGURATION la compone/configura en editor; EXTENSION propone un ajuste puntual a una pieza existente; CUSTOM identifica una brecha concreta del patrón solicitado; PROTOTYPE ONLY no se migra como función comercial; PENDING exige comprobar composición. Las clases son recomendaciones de resolución, no autorizaciones para crear archivos.

Las tablas A y B se unen por ID y forman una única matriz. En A, TSX es relativo a `src/` salvo indicación; SCSS es relativo a `src/`. En B, archivos nativos son relativos a T. Los IDs de settings/blocks se contrastaron con schemas y snippets; no son nombres de settings propuestos. «—» significa no aplica.

## Verificaciones que condicionan las propuestas

1. **Texto fijo y slider:** image-with-text solo expone una imagen desktop/mobile; multiple-media-with-text permite como máximo dos medios y no contiene el slider de tres imágenes de story-origin. Slideshow cambia slides completos. Esa brecha justifica evaluar un componente editorial propio pequeño; no copiar el motor del carrusel ni convertir todos los splits en secciones nuevas.
2. **Care:** el patrón sincroniza cinco estados de un SVG y navegación/scroll. FAQ, tabs y timeline cubren contenido y navegación parcial; no el mismo estado de ilustración. Elegir entre simplificar a nativo o aprobar ese patrón custom.
3. **Precios/badges:** price-list admite producto/variante/line_item y money/money_with_currency. product-badges usa custom.badges, show_discount y discount_mode (saving/percentage), además de locales. Son capacidades ya existentes; la precisión gráfica o la línea «Ahorras» no justifica sustituir cálculos o eventos comerciales. Probar variantes con comparativos heterogéneos: el snippet contiene condiciones de producto y variante que no deben asumirse idénticas al React.
4. **Hero video:** el slideshow local renderiza ramas desktop y mobile separadas; no se ha demostrado que equivalga a la selección única del React. Video nativo y media son alternativas para evaluar antes de escribir un reproductor propio.
5. **H1:** header.liquid crea un H1 en Home. La jerarquía se revisa en la página completa; no trasladar automáticamente headingLevel=1 del prototipo al hero.
6. **Dynamic Grid:** `_dynamic-grid-item` referencia `subheading`, pero falta `blocks/subheading.liquid`. No usar esa ruta como solución confirmada para M34 ni crear el archivo faltante por inferencia. Contrastar paquete/proveedor en una fase autorizada.
7. **Favicon:** theme.liquid solo expone el favicon nativo con image_picker/raster. El SVG adaptable del prototipo no se copia a un hook global como preparación; se decide si basta el control nativo o se solicita una excepción concreta.
8. **Estado ya existente:** header.liquid carga `rsm-header.css` y usa `rsm-liquid-glass-dark`; header-group guarda show_locale_selector=true y scheme-4. Las guías históricas de noviembre que describen ausencia de custom o selector apagado no representan esa copia actual. La presencia local no certifica QA remoto.

## Política de implementación futura

Core comercial intacto: product form, variantes, galería, Quick Buy, carrito, localización y foco se reutilizan. Crear `rsm-*` solo tras aprobar una brecha específica y su alcance. Los nombres de archivos propios aquí descritos son candidatos, **no se crearon en T**. CSS y JavaScript propios se cargan desde el componente propietario; no hay autorización para un hook global en theme.liquid. Los schemas y contenido deben permanecer editables/traducibles en es/en.

Las personalizaciones potenciales pueden disminuir si RSM acepta la composición nativa. No se exige portabilidad literal de todos los props React. La documentación histórica del tema propone escenarios, no instrucciones para replicar un bento que el prototipo actual no contiene.
